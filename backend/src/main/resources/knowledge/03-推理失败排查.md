# 推理失败排查手册

按错误码对照排查，绝大多数问题都能在这里定位。

## 401 未登录或登录已过期

表现：接口返回「未登录或登录已过期，请重新登录」。

原因与处理：

1. 令牌过期（开发环境 24 小时，生产环境 2 小时）→ 重新登录；
2. 已点击过「退出登录」→ 该令牌已进入黑名单，必须重新登录；
3. 管理员重置了你的密码 → 旧令牌会立即失效，用临时密码重新登录并修改。

## 403 权限不足

表现：普通用户访问 `/api/admin/**` 时报「权限不足」。

说明：管理接口只对 `admin` 角色开放。普通用户不需要也不应该调用这些接口。

## 404 模型不存在

可能原因：

1. 模型 id 填错；
2. 该模型已被**逻辑删除**（`status = -1`），后台仍能看到，但公开接口一律不可见；
3. 该模型被**下架**（`status = 0`），公开详情与推理都会被拒绝。

处理：到「产品服务」页确认模型当前是否在线；不要在代码里写死模型 id。

## 400 模型未上线，无法调用

表现：推理接口返回「模型未上线，无法调用」。

原因：模型存在但 `status != 1`。平台在调用模型服务**之前**就做了这个校验，
这是为了避免把请求转发给一个没有加载模型的服务，白等超时。

## 400 模型未配置有效的 model_api

原因：后台新建模型时 `model_api` 为空。该字段存的是推理服务里的模型 key
（如 `resnet50`），不是 URL。

处理：管理员在后台补填 `model_api` 后再试。

## 400 文件大小 / 类型不符

- 超过 5MB → 压缩或换更小的图；
- 格式不在白名单（JPG/PNG/WEBP/GIF/BMP）→ 转成 PNG 再传。

## 429 请求过于频繁

平台对推理接口按用户限流：**每个用户 60 秒内最多 20 次**，网页端与 Agent 共用同一额度。

处理：等待窗口滚动（约 1 分钟）后重试；批量任务请降低频率。

## 502 推理服务异常

表现：「模型服务暂时不可用」或上游 500。

排查顺序：

1. 模型服务是否在运行（默认端口 8001，健康检查 `/health`）；
2. 该模型的权重文件是否齐全；
3. 若只有某一个模型失败、其他模型正常，通常是该模型的权重或依赖缺失，
   而不是整个服务挂了。

## 图片链接为空但推理成功

这是**预期行为**：对象存储（MinIO）不可用时，平台选择「继续推理、只是不保存图片链接」，
而不是让整次推理失败。推理记录仍会写入，`file_url` 为空。

## 结果置信度很低（低于 0.6）

不代表接口出错，通常意味着：

1. 输入与模型训练分布差异大（例如用日常物体模型看医学影像）；
2. 图片模糊、主体不突出；
3. 语言不匹配（英文模型跑中文文本）。

处理：换更匹配的模型，或换更清晰的输入。低置信度结果不建议直接作为业务结论。
